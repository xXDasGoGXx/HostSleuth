# v1.1.0 — Event Timeline Quality

Date: 2026-10-15
Owner request: "look at HostSleuth on GitHub and live, and make it better."

## What live showed (v1.0.1 on OMV, Docker mode)

- 94 of the 100 retained events were listener churn, not service changes:
  wsdd/avahi binds on every Docker veth and bridge (`fe80::…%vethX:3702`,
  `[ff02::c]%br-…:3702`, `tcp …:5357`), per-bridge `172.x.0.1:5353`, and
  ephemeral UDP client sockets (`udp *:45902` → `udp *:45591`).
- One reboot alone produced 69 events in one minute. The reboot event itself
  and earlier history had been pushed out of the 100-event window, so the
  Changes view and the Reboot/Incident stories lost real context.
- `/api/about` reported `revision: ""`: `.dockerignore` excludes `.git`, so the
  Go toolchain could not embed VCS information in container builds.
- `events.jsonl` was append-only with no bound and is read in full on every
  timeline request.
- The HTTP server had no read/header/idle timeouts on a LAN-bound port.

## What changed

1. Listener churn classification (`internal/core/listener_noise.go`):
   link-local/multicast sockets, discovery-protocol binds on a specific
   interface address (mDNS 5353, LLMNR 5355, SSDP 1900, WS-Discovery
   3702/5357), and UDP sockets in 32768–60999 (except WireGuard 51820 and
   Tailscale 41641) are no longer recorded as changes. They remain in the
   Snapshot as current evidence. TCP LISTEN sockets are always recorded;
   wildcard discovery binds (the daemon itself) are still recorded.
2. Reading the timeline skips churn recorded by earlier versions before the
   limit is applied, so existing installs recover their real history
   immediately. Raw view: `hostsleuth events --all`, `/api/events?all=1`.
3. Timeline compaction past 4 MiB: atomic rewrite (mode 0600) keeping the
   newest 5,000 meaningful events.
4. Build revision passed explicitly (`-X main.revision`) in the Dockerfile and
   release workflow; Docker smoke CI now asserts it.
5. HTTP server timeouts: 10 s header, 30 s read, 120 s idle, 64 KiB headers.
   No write deadline, because diagnosis stories can take tens of seconds.

## Unchanged

Snapshot schema (still 4), event record format, API response shapes, Evidence
Bundle format, Safe Actions, privileges, and the read-only boundary.
Rolling back to v1.0.1 reads the same files.

## Validation

`gofmt`, `go vet`, full `go test ./...`, `go test -race ./internal/core`, and a
served end-to-end check: a seeded timeline of 1 reboot + 120 multicast churn
lines + 1 container-health warning returned exactly the reboot and the
warning by default, 100 raw events with `?all=1`, and `/api/about` carried the
build revision.
