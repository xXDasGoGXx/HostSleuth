# v1.5.0 — Why it is unhealthy

Date: 2026-10-19
Owner request (2026-10-16, after the Backblaze uploader showed *unhealthy* for an hour): "it would
be nice to have HostSleuth tell me why it is unhealthy, or at least suggest why, instead of going
hmmmm."

## Evidence

- The field-limited `docker inspect` template gains two fields: `Config.Healthcheck.Test` (quoted
  with Docker's `json`) and `State.Health.Log` as `exit|end|json(output)` records. Both are read with
  `with`/`index`, so containers without a health check do not fail the template. A test executes the
  template with `missingkey=error` and a `json` function like Docker's; the forbidden-field test now
  allows `json` only around `Test` and a result's `Output`.
- Only the newest result is kept. Command and output are masked (URL credentials, `-p`/`--password`/
  `--token`/`--api-key` values, `-u user:pass`, authorization/cookie headers, `key=value` secrets,
  private keys), whitespace-collapsed and bounded (400/300 characters). Evidence Bundle and Share
  redaction treat both as free text.

## Explanation rules (`internal/core/container_health.go`)

Summary, in order of preference: what the output means (timeout, connection refused, DNS, HTTP
4xx/5xx, missing command/permission denied); for file-only checks, a negative condition on a
problem-named file ("Most likely … UNCLASSIFIED.txt is not empty"); a two-file comparison
("probably catching up with <peer>" when a container in the same compose project changed just
before, or "waiting to catch up … cleared on its own after N" from its own history); otherwise
the printed text or exit code. Clues: what changed within ten minutes before it began (itself, same
stack, host), earlier episodes this week and how they cleared, and the failing streak.

## Where it shows

Replay headline (second line) and detail panel at the latest moment; Container Story card and its
Copy/Share summary; `why` in `/api/replay` parts, `/api/container-story` and
`hostsleuth containers NAME`.
