# v1.2.0 — Listener blips, container health, tablet console

Date: 2026-10-15
Owner request: build the reboot-wave fix, then review the GUI and the rest of HostSleuth and make
it better.

## Method

The console was rendered in headless Chromium at iPad landscape (1180×820), iPad portrait
(820×1180), desktop and phone widths, with the live OMV snapshot (345 listeners, 49 interfaces,
25 containers) and timeline substituted for the API responses. Problems below were seen there,
not inferred.

## Found

- After the 2026-10-14 reboot the first post-boot snapshot recorded 42 listeners as disappeared
  and the next one recorded them as appeared. Those 84 lines filled the 100-event window, so the
  reboot record itself (written first in the same snapshot) was just out of view. Reboot Story
  also counted those returned listeners as post-boot problem warnings.
- Overview said "25/25 containers running" while `backblaze-snapshotter` was unhealthy; nothing
  on the page said so.
- Links to Reboot, Workbench, Actions and the other added views opened Overview, and the
  browser back/forward buttons did not change views (no `hashchange` handling).
- Overview identity tiles truncated at iPad landscape ("openmedi…", "Debian GN…").
- Reachability counted 327 sockets "beyond loopback", most of them routine churn; `127.0.0.53`
  (systemd-resolved) was classed as a specific address, not loopback.
- Host evidence was 21,000 px tall: every socket, every veth interface, no filter, unsorted.
  Routes were all titled "Route"; memory showed as `32777728 kB`.
- Changes was a flat list; each row's "Inspect window" button took its own row.
- Reboot and Incident Lens cards had no inner padding.
- Actions over the LAN showed a bare "loopback only" line above empty forms; in Docker mode the
  capability reason suggested `--enable-actions`, which can never help there.

## Changed

- `internal/core/listener_blips.go`: a listener that disappears and the same socket reappearing
  within 15 minutes are collapsed into one summary per snapshot ("34 listeners went away after
  the host reboot and were back within 61s: …"); info after a recorded reboot, warning
  otherwise. Non-returning listeners keep their own warning. Applied in `ReadEvents` (UI, API,
  Evidence Bundle, Reboot Story, Incident Lens). `ReadDetailedEvents` keeps every event for
  Service Story's per-port correlation. The timeline file is unchanged.
- Docker-mode capability reason checked before the `--enable-actions` reason.
- Console (`app.js`, `actions.js`, `reboot_story.js`, `incident_lens.js`, new `console_v3.css`):
  every view is linkable and back/forward works; unhealthy/restarting/stopped containers lead the
  attention card, the Containers tile and the Host container list; identity tiles wrap; routine
  sockets are excluded from counts and the overview preview and hidden behind a toggle on Host,
  with a search box; IPv4/IPv6 wildcard pairs merge into one row; well-known ports get a
  "usually SSH"-style hint (a hint, not evidence); listeners order wildcard → specific →
  loopback, then by port; interfaces put addressed physical links first and fold veth/vnet/tap
  away; routes are titled by destination; memory in GiB; Changes has category and
  warnings-only filters and day headings with time-only rows; Reboot builds itself on open;
  Actions shows one clear explanation over the LAN or when nothing is available.

## Unchanged

Snapshot schema 4, event record format, API shapes, Evidence Bundle format, Safe Actions and
their loopback boundary, privileges. Rollback to 1.1.0 or 1.0.1 reads the same files.

## Validation

- `gofmt`, `go vet`, full `go test ./...`; new tests replay a sanitized copy of the real OMV
  timeline (`internal/core/testdata/omv_reboot_timeline.json`, documentation addresses and
  generic container names) plus partial-return, repeated-outage and passthrough cases.
- Go and JavaScript routine-socket classifiers agree on all 32 table cases and on the 345 live
  sockets (235 routine).
- Headless interaction checks at 1180×820 and 375×812: filters (33 → 14 warnings, 13 container),
  day headings, socket search (`22` → 3 rows, "IPv4 + IPv6 · usually SSH"), routine toggle
  (83 → 318 rows), unhealthy container first, back/forward, `#actions` deep link, LAN Actions
  message, no horizontal scroll, no script errors.
