## Container lifecycle evidence

- `docker inspect` with a field-limited template: image ID, `org.opencontainers.image.version`,
  restart count, start/finish time, exit code, OOM flag, health failing streak. A unit test forbids
  `.Env`, `.Cmd`, `.Mounts`, `.HostConfig`, `.Args`, `.Entrypoint` and whole-object `json`.
- `docker events --filter event=die --filter event=oom` over a bounded 30-minute window, reading
  only time, action, name and exit code; an `oom` within 10 s before a `die` marks that exit as
  out-of-memory. Docker resets a running container's exit code to 0, so this log is the only
  reliable source for why the previous run ended.
- New change events: `container updated: NAME: IMAGE[, version A → B]` (new build behind the same
  tag included; no image digests in text), `container recreated: NAME (same image)`, and
  `container restarted: NAME (killed for running out of memory | crashed, exit code N | killed with
  SIGKILL, exit code 137 | stopped by SIGTERM, exit code 143 | stopped cleanly, exit code 0)`.
  If the event log did not cover a restart: `(how the previous run ended was not reported)`.
- Baselining: values must exist on both sides, so upgrading never replays history; exits are only
  reported after the previous snapshot and only when the container is running again (a container
  that stays down is already reported by its status change).
- Snapshot schema stays 4; the new `ContainerInfo` fields are optional. The Evidence Bundle
  aliases image IDs and redacts the new fields.

## Container Story

`/api/containers`, `/api/container-story?name=`, `hostsleuth containers [NAME]`, Containers view:
troubled first (unhealthy, restarting, crash-looping ≥3 crashes in 7 days, stopped, unstable),
restarts 24 h / 7 d, crashes, OOM kills, unhealthy episodes, last update; per container a
deterministic conclusion, its 7-day timeline, and listener changes on the host ports it publishes
within two minutes of its restarts, updates or failures (time-proximity context only for
host-network containers). Overview's Containers tile adds "N restarts today" and its attention
button opens Containers.

## Share redacted

`POST /api/share` (≤64 KiB, stores nothing) applies the Evidence Bundle redaction seeded with the
current snapshot. Every result view has **Share redacted** beside **Copy evidence summary**, with
a dialog to copy or download Markdown.

## Caught by the real-Docker CI check

The first CI run failed: Docker evaluates `inspect` templates against the decoded JSON map with
missing keys as errors, so `{{if .State.Health}}` failed the whole command whenever any container
had no healthcheck (no image IDs or start times were recorded). The exit-log half already worked
(`container restarted: hs-crashloop (crashed, exit code 3)` was recorded three times). Fixed by
reading optional `State.Health` with `index`; a unit test now executes the template with
`missingkey=error` on a map and fails on the old template with the same error CI reported. CI
failure diagnostics are written as annotations, because job logs are not downloadable from the
agent session.
